## 10.4 P2P 패러다임 (Peer-to-Peer Paradigm)

### 1. P2P 네트워크 개요
- **정의**: 인터넷 사용자들이 자신의 자원을 공유하며 대등한 자격으로 네트워크를 구성하는 방식.
- **주요 이슈**: 참여하는 구성원(Peer)과 접근 가능한 파일의 위치를 찾는 것.
- **분류**:
    - **집중적 네트워크 (Centralized Network)**: 냅스터(Napster) 등.
    - **분권적 네트워크 (Decentralized Network)**: 그누텔라(Gnutella), 비트토런트(BitTorrent) 등.

### 2. 집중적 네트워크 (Centralized Network)
- **혼합형 P2P**: 클라이언트-서버 방식(디렉토리 검색) + P2P 방식(파일 전송) 혼합.
- **동작**:
    1. 피어가 중앙 서버에 파일 위치 문의.
    2. 중앙 서버는 파일을 가진 피어들의 IP 주소 목록 반환.
    3. 피어는 목록 중 하나에 직접 접속하여 파일 다운로드.
- **단점**: 중앙 서버에 부하 집중, 단일 실패 지점(Single Point of Failure).

### 3. 분권적 네트워크 (Decentralized Network)
- **비체계적 (Unstructured)**:
    - 디렉토리가 랜덤하게 분산됨.
    - 질의를 **플러딩(Flooding)** 방식으로 전파하므로 탐색이 비효율적 (예: Gnutella).
- **체계적 (Structured)**:
    - **DHT (Distributed Hash Table)**를 사용하여 효율적인 탐색 보장.

### 4. 분산 해시 테이블 (DHT)
- **개념**: 데이터(또는 참조)를 미리 정의된 규칙에 따라 노드들에 분산 저장.
- **주소 공간**: $2^m$ 크기의 링(Ring) 형태 주소 공간 사용.
- **해싱**:
    - **노드 ID**: IP 주소 등을 해싱하여 $m$비트 정수로 변환.
    - **키 (Key)**: 파일 이름 등을 해싱하여 $m$비트 정수로 변환.
- **저장 방식**:
    - **직접적 방법**: 키와 가장 가까운 노드에 실제 데이터 저장.
    - **간접적 방법**: 키와 가장 가까운 노드에 **참조(Reference)**만 저장 (대부분 이 방식 사용).

#### A. 코드 (Chord)
- **식별자 공간**: $m$비트 식별자 링.
- **다음 노드 (Successor)**: $N \ge k$인 가장 가까운 노드에 키 $k$ 저장.
- **핑거 테이블 (Finger Table)**:
    - 각 노드는 $m$개의 항목을 가진 라우팅 테이블 유지.
    - $i$번째 항목은 $N + 2^{i-1}$보다 크거나 같은 첫 번째 노드(Successor)를 가리킴.
    - 이를 통해 탐색 범위를 절반씩 줄여나가 $O(\log N)$의 탐색 성능 보장.
- **안정화 (Stabilization)**: 노드의 가입/탈퇴 시 주기적으로 핑거 테이블 갱신.

#### B. 패스트리 (Pastry)
- **식별자 공간**: $2^b$ 진법의 $n$자리 숫자로 표현 ($m=128, b=4$일 때 16진수 32자리).
- **라우팅 테이블**: 접두사(Prefix) 매칭 기반.
    - 공통 접두사 길이가 길어지는 방향으로 라우팅.
- **리프 셋 (Leaf Set)**: 자신과 수치적으로 가장 가까운 $2^b$개의 노드 집합 유지.

#### C. 카뎀리아 (Kademlia)
- **거리 측정**: **XOR 연산** 사용 ($d(x, y) = x \oplus y$).
- **K-버킷 (K-Buckets)**:
    - 라우팅 테이블의 각 행에 $k$개의 노드 정보를 유지 (보통 $k=20$).
    - 노드 실패에 대한 중복성(Redundancy) 제공.
- **특징**: 대칭적 거리 구조로 인해 노드 탐색과 라우팅이 효율적.

### 5. 비트토런트 (BitTorrent)
- **토런트 (Torrent)**: 파일 공유를 위한 협력 그룹.
- **동작 원리**:
    - 파일을 작은 조각(Piece)으로 나눔.
    - **Tit-for-Tat (치고받기)**: 나에게 데이터를 준 사람에게 나도 데이터를 줌.
    - **Rarest-First**: 가장 희귀한 조각부터 먼저 다운로드하여 전체 가용성 증대.
- **추적자 (Tracker)**: 피어들의 정보를 관리하는 서버. (Trackerless 모드에서는 DHT 사용).
- **Choking/Unchoking**: 대역폭 관리를 위해 일정 수의 피어와만 데이터 교환.

## 10.5 소켓 인터페이스 프로그래밍

### 1. 소켓 데이터 구조 (C언어)
- **계열 (Family)**: `PF_INET` (IPv4), `PF_INET6` (IPv6).
- **유형 (Type)**: `SOCK_STREAM` (TCP), `SOCK_DGRAM` (UDP), `SOCK_RAW`.
- **주소 구조체**: `struct sockaddr_in` (IP 주소, 포트 번호 포함).

### 2. UDP 소켓 프로그래밍
- **특징**: 비연결형이므로 `connect()` 과정이 필요 없음.
- **함수**:
    - `socket()`: 소켓 생성.
    - `bind()`: 소켓에 주소 할당 (서버).
    - `sendto()`: 데이터 전송 (목적지 주소 명시).
    - `recvfrom()`: 데이터 수신 (발신자 주소 획득).
- **흐름**:
    - 서버: socket -> bind -> recvfrom (대기) -> sendto.
    - 클라이언트: socket -> sendto -> recvfrom.

### 3. TCP 소켓 프로그래밍
- **특징**: 연결형이므로 연결 설정 과정 필요.
- **함수**:
    - `socket()`: 소켓 생성.
    - `bind()`: 소켓에 주소 할당 (서버).
    - `listen()`: 연결 요청 대기 상태로 전환 (서버).
    - `accept()`: 연결 요청 수락 및 새로운 소켓 생성 (서버).
    - `connect()`: 서버에 연결 요청 (클라이언트).
    - `send() / recv()`: 데이터 송수신 (또는 `write() / read()`).
    - `close()`: 연결 종료.
- **흐름**:
    - 서버: socket -> bind -> listen -> accept (블로킹) -> recv -> send -> close.
    - 클라이언트: socket -> connect -> send -> recv -> close.
- **반복 서버 (Iterative Server)**: 한 번에 하나의 클라이언트만 처리.
- **동시 서버 (Concurrent Server)**: `fork()`나 스레드를 사용하여 여러 클라이언트 동시 처리 (교재에서는 반복 서버 위주 설명).
