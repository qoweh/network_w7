# 8장 네트워크층: 패킷의 라우팅 (Network Layer: Packet Routing)

이 문서는 `ch 08 packet routing.pdf` 파일의 내용을 바탕으로 **8.1 개요**, **8.2 라우팅 알고리즘**, **8.3 유니캐스트 라우팅 프로토콜**, **8.4 멀티캐스트 라우팅**, **8.5 IGMP**에 대해 상세하게 정리한 것입니다.

## 8.1 개요 (Overview)

### 1. 포워딩 테이블 (Forwarding Table)
- **발신지 라우터**: 패킷을 목적지로 보내기 위해 기본 라우터(Default Router)로 전송합니다.
- **목적지 라우터**: 패킷을 최종 목적지 호스트로 전달합니다.
- **라우팅**: 발신지 라우터에서 목적지 라우터까지 패킷을 전달할 **중간 라우터들을 결정**하는 과정입니다. 이를 위해 경로 설정이 필요합니다.

### 2. 최소 비용 라우팅 (Least Cost Routing)
- **네트워크 모델링**: 네트워크를 노드(라우터)와 링크(연결)로 구성된 **가중치 그래프**로 모델링합니다. 링크의 가중치(비용)는 라우팅 목적(속도, 거리, 비용 등)에 따라 달라질 수 있습니다.
- **최적 경로**: 발신지에서 목적지까지의 총 비용이 최소가 되는 경로를 의미합니다.
- **최소 비용 트리 (Least Cost Trees)**:
    - $N$개의 라우터가 있는 네트워크에는 각 라우터를 루트로 하는 $N$개의 최소 비용 트리가 존재합니다.
    - **특징**: 어떤 두 노드 사이의 최소 비용 경로는 유일하며, 역방향 경로도 동일한 비용을 가집니다(대칭적일 경우).

## 8.2 라우팅 알고리즘 (Routing Algorithms)

### 1. 거리-벡터 라우팅 (Distance-Vector Routing)
- **개념**: 각 라우터가 전체 네트워크에 대한 거리(비용) 정보를 **벡터(Vector)** 형태로 관리합니다.
- **동작 원리**:
    - 초기에는 인접한 이웃 라우터와의 거리 정보만 가집니다.
    - 주기적으로 이웃 라우터와 벡터 정보를 교환하며, **벨만-포드(Bellman-Ford) 방정식**을 이용해 경로를 갱신합니다.
    - $D_{xy} = \min_v \{ c_{xv} + D_{vy} \}$ (x에서 y까지의 최소 비용은, 이웃 v까지의 비용 + v에서 y까지의 최소 비용 중 최솟값)
- **문제점**:
    - **무한대로의 카운트 (Count to Infinity)**: 링크 단절 시, 잘못된 정보가 루프를 돌며 비용이 무한히 증가하는 현상.
    - **해결책**:
        - **수평 분할 (Split Horizon)**: 정보를 받은 인터페이스로는 해당 정보를 다시 보내지 않음.
        - **포이즌 리버스 (Poisoned Reverse)**: 정보를 받은 인터페이스로 보낼 때는 비용을 무한대($\infty$)로 설정하여 보냄.

### 2. 링크-상태 라우팅 (Link-State Routing)
- **개념**: 각 라우터가 자신의 **모든 링크 상태** 정보를 전체 네트워크에 **플러딩(Flooding)**하여 공유합니다.
- **동작 원리**:
    - **LSP (Link-State Packet)**: 이웃 노드 및 링크 비용 정보를 담은 패킷 생성.
    - **LSDB (Link-State Database)**: 모든 라우터로부터 받은 LSP를 모아 전체 네트워크 지도를 만듭니다. (모든 라우터가 동일한 LSDB 보유)
    - **다익스트라(Dijkstra) 알고리즘**: LSDB를 바탕으로 자신을 루트로 하는 최소 비용 트리를 계산하여 포워딩 테이블을 생성합니다.

### 3. 경로-벡터 라우팅 (Path-Vector Routing)
- **개념**: 최소 비용보다는 **정책(Policy)**을 기반으로 경로를 선택할 때 사용합니다. (예: 특정 AS를 경유하지 않음)
- **동작 원리**:
    - 거리 대신 **경로(Path)** 자체(거쳐가는 노드들의 목록)를 벡터로 교환합니다.
    - **스패닝 트리**: 발신지의 정책에 따라 트리를 결정합니다.
    - **루프 방지**: 경로 목록에 자신의 ID가 있으면 해당 경로를 버립니다.

## 8.3 유니캐스트 라우팅 프로토콜 (Unicast Routing Protocols)

인터넷은 여러 개의 **자율 시스템(AS, Autonomous System)**으로 구성된 계층적 구조를 가집니다.

### 1. 자율 시스템 (AS)
- 하나의 관리 주체 하에 있는 네트워크 및 라우터들의 집합입니다.
- **AS 종류**:
    - **Stub AS**: 하나의 다른 AS와만 연결됨 (경유 불가).
    - **Multihomed AS**: 여러 AS와 연결되나, 트래픽 경유는 허용 안 함.
    - **Transient AS**: 여러 AS와 연결되며 트래픽 경유 허용 (백본 등).

### 2. 인트라도메인 (Intra-domain) 라우팅 프로토콜 (IGP)
AS 내부에서 사용되는 프로토콜입니다.

#### A. RIP (Routing Information Protocol)
- **기반**: 거리-벡터 (Distance-Vector) 알고리즘.
- **메트릭**: **홉 카운트 (Hop Count)** (최대 15, 16은 무한대).
- **동작**: 30초마다 이웃에게 라우팅 테이블 전체를 전송(UDP 포트 520).
- **특징**: 구현이 간단하지만, 규모가 큰 네트워크에는 부적합합니다.

#### B. OSPF (Open Shortest Path First)
- **기반**: 링크-상태 (Link-State) 알고리즘.
- **메트릭**: 대역폭, 지연시간 등을 고려한 가중치.
- **계층적 구조**: AS를 여러 **지역(Area)**으로 나누어 트래픽을 분산시킵니다.
    - **백본 지역 (Backbone Area)**: 모든 지역 연결 담당.
    - **LSA (Link-State Advertisement)**: 링크 상태 광고 메시지 (Router Link, Network Link, Summary Link 등).
- **특징**: 수렴이 빠르고 루프가 없으며, 대규모 네트워크에 적합합니다.

### 3. 인터도메인 (Inter-domain) 라우팅 프로토콜 (EGP)
AS 간에 사용되는 프로토콜입니다.

#### BGP4 (Border Gateway Protocol version 4)
- **기반**: 경로-벡터 (Path-Vector) 알고리즘.
- **특징**: 현재 인터넷의 표준 인터도메인 프로토콜. **TCP** 연결을 통해 신뢰성 있게 정보를 교환합니다.
- **구분**:
    - **eBGP (External BGP)**: 서로 다른 AS의 경계 라우터 간 통신.
    - **iBGP (Internal BGP)**: 같은 AS 내의 라우터 간 통신 (외부 경로 정보 전파).
- **경로 속성 (Path Attributes)**:
    - **AS-PATH**: 경로상에 있는 AS들의 리스트 (루프 방지).
    - **NEXT-HOP**: 다음 홉 라우터의 IP 주소.
    - **LOCAL-PREF**: AS 내부에서 외부로 나갈 때의 우선순위.
    - **MULTI-EXIT-DISC (MED)**: 외부에서 AS로 들어올 때의 우선순위.

## 8.4 멀티캐스트 라우팅 (Multicast Routing)

### 1. 개념
- **유니캐스팅**: 1:1 통신.
- **멀티캐스팅**: 1:N (그룹) 통신. 송신자는 한 번 보내고, 라우터가 패킷을 복사하여 그룹 멤버가 있는 경로로만 전달합니다.

### 2. 프로토콜 종류
#### A. DVMRP (Distance Vector Multicast Routing Protocol)
- RIP 확장. **RPF (Reverse Path Forwarding)**를 사용하여 소스 기반 트리를 만듭니다.
- **RPB (Broadcasting)** 후 **RPM (Pruning, 가지치기)**을 통해 불필요한 경로를 제거합니다.

#### B. MOSPF (Multicast OSPF)
- OSPF 확장. 링크 상태 DB에 그룹 멤버십 정보를 추가하여, 각 소스마다 최단 경로 트리를 계산합니다.

#### C. PIM (Protocol Independent Multicast)
- 특정 유니캐스트 프로토콜에 종속되지 않습니다.
- **PIM-DM (Dense Mode)**: 밀집 모드. DVMRP처럼 일단 뿌리고 가지치기 (Flood and Prune).
- **PIM-SM (Sparse Mode)**: 성긴 모드. **RP (Rendezvous Point)**라는 중심 라우터를 정해두고, 가입 요청이 오면 트리를 연결하는 방식 (Join 메시지 기반).

## 8.5 IGMP (Internet Group Management Protocol)

### 1. 역할
- 호스트와 라우터 사이에서 **멀티캐스트 그룹 멤버십**을 관리하는 프로토콜입니다.
- 라우터가 "이 네트워크에 특정 그룹에 관심 있는 호스트가 있는가?"를 파악하게 해줍니다.

### 2. 동작 과정
- **질의 (Query)**: 라우터가 주기적으로 서브넷 내의 호스트들에게 보냅니다. (General Query, Group-Specific Query 등)
- **보고 (Report)**: 호스트가 그룹에 가입하거나, 질의에 응답할 때 보냅니다.
- **탈퇴 (Leave)**: 호스트가 그룹을 떠날 때 보냅니다 (IGMPv2 이상).

### 3. 메시지 형식
- IP 데이터그램에 캡슐화되며, 프로토콜 번호는 2번입니다.
- **TTL = 1**로 설정되어 로컬 네트워크를 벗어나지 않습니다.
