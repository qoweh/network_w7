# 9장 전송층 (Transport Layer) - Part 1

이 문서는 `ch 09 transport (1).pdf` 파일의 내용을 바탕으로 **9.1 전송층 서비스**, **9.2 전송층 프로토콜**, **9.3 UDP**, **9.4 TCP (일부분)**에 대해 상세하게 정리한 것입니다.

## 9.1 전송층 서비스 (Transport Layer Services)

### 1. 개요
- **위치**: 응용층(Application Layer)과 네트워크층(Network Layer) 사이에 위치합니다.
- **역할**: **프로세스-대-프로세스(Process-to-Process)** 통신을 제공합니다.
    - 네트워크층은 호스트-대-호스트 통신을 담당하지만, 전송층은 호스트 내의 특정 프로세스까지 데이터를 전달합니다.
- **논리적 연결**: 서로 다른 지역에 있는 두 응용 프로세스가 마치 직접 연결된 것처럼 메시지를 주고받을 수 있게 합니다.

### 2. 포트 번호 (Port Number)
- **정의**: 다중 사용자/다중 프로세스 환경에서 특정 프로세스를 식별하기 위한 16비트 식별자입니다.
- **클라이언트-서버 패러다임**:
    - **서버**: 잘 알려진 포트(Well-known port)를 사용합니다. (예: HTTP 80, DNS 53)
    - **클라이언트**: 임시 포트(Ephemeral port) 또는 단기 포트(Short-lived port)를 동적으로 할당받아 사용합니다.
- **소켓 주소 (Socket Address)**: **IP 주소 + 포트 번호**의 조합으로, 특정 호스트의 특정 프로세스를 유일하게 식별합니다.
- **ICANN 범위**:
    - **Well-known ports (0~1023)**: 시스템(루트) 권한 필요, 주요 프로토콜용.
    - **Registered ports (1024~49151)**: 특정 응용 프로그램을 위해 등록된 포트.
    - **Dynamic/Private ports (49152~65535)**: 클라이언트가 임시로 사용하는 포트.

### 3. 주요 기능
- **캡슐화와 역캡슐화**:
    - 송신측: 응용층 메시지에 전송층 헤더를 붙여 캡슐화.
    - 수신측: 헤더를 제거하고 메시지를 응용층으로 전달.
- **다중화(Multiplexing) 및 역다중화(Demultiplexing)**:
    - **다중화**: 여러 응용 프로세스의 데이터를 하나의 전송층 링크로 보냄 (Many-to-One).
    - **역다중화**: 수신된 데이터를 적절한 응용 프로세스로 분배 (One-to-Many).
- **흐름 제어 (Flow Control)**:
    - 생산자(송신자)와 소비자(수신자) 사이의 속도 차이를 조절하여 **버퍼 오버플로우**를 방지합니다.
    - **Pushing**: 생산자가 데이터를 밀어넣음.
    - **Pulling**: 소비자가 데이터를 요청함.
    - 전송층에서는 4개의 개체(송신 프로세스, 송신 TCP, 수신 TCP, 수신 프로세스) 간의 상호작용으로 이루어집니다.
- **오류 제어 (Error Control)**:
    - 손상된 패킷 검출 및 폐기.
    - 손실된 패킷 재전송.
    - 중복 패킷 폐기.
    - 순서가 뒤바뀐(Out-of-order) 패킷 버퍼링 및 재정렬.
    - **순서 번호(Sequence Number)**와 **확인 응답(Acknowledgement)**을 사용합니다.

### 4. 서비스 유형
- **비연결형 (Connectionless)**: 패킷들이 서로 독립적이며, 순서가 보장되지 않음 (예: UDP).
- **연결형 (Connection-oriented)**: 전송 전 연결 설정, 데이터 전송, 연결 해제 단계를 거치며 순서와 신뢰성 보장 (예: TCP).

## 9.2 전송층 프로토콜 (Transport Layer Protocols)

### 1. 프로토콜 종류
- **UDP (User Datagram Protocol)**: 신뢰성 없는 비연결형 프로토콜. 단순하고 빠름.
- **TCP (Transmission Control Protocol)**: 신뢰성 있는 연결형 프로토콜. 흐름/오류 제어 제공.
- **SCTP (Stream Control Transmission Protocol)**: UDP와 TCP의 특성을 결합한 프로토콜.

### 2. 주요 포트 번호 (Well-known Ports)
| Port | Protocol | Description |
|:---:|:---:|:---|
| 7 | Echo | 수신한 데이터그램 반송 |
| 20, 21 | FTP | 파일 전송 (20: 데이터, 21: 제어) |
| 23 | Telnet | 원격 터미널 접속 |
| 25 | SMTP | 이메일 전송 |
| 53 | DNS | 도메인 이름 시스템 |
| 67 | DHCP | 동적 호스트 설정 |
| 80 | HTTP | 웹 서비스 |

## 9.3 사용자 데이터그램 프로토콜 (UDP)

### 1. 특징
- **비연결형**: 연결 설정 과정이 없습니다.
- **비신뢰성**: 흐름 제어, 오류 제어(재전송)를 제공하지 않습니다.
- **단순성**: 헤더가 작고(8바이트) 처리가 빠릅니다.

### 2. 헤더 형식 (8 Bytes)
- **발신지 포트 (Source Port)**: 16비트.
- **목적지 포트 (Destination Port)**: 16비트.
- **전체 길이 (Total Length)**: 16비트. 헤더 + 데이터 길이 (최대 65,535 바이트).
- **검사합 (Checksum)**: 16비트. 오류 검출용 (선택 사항이지만 권장).
    - **의사 헤더 (Pseudo Header)**: IP 헤더의 일부(발신지 IP, 목적지 IP 등)를 포함하여 계산함으로써, 패킷이 엉뚱한 호스트로 전달되는 것을 방지합니다.

### 3. UDP 응용
- **단순 요청-응답**: DNS, DHCP (오버헤드 최소화).
- **실시간 멀티미디어**: VoIP, 스트리밍 (약간의 손실보다 실시간성이 중요).
- **멀티캐스팅**: 1:N 통신에 적합.
- **관리 프로토콜**: SNMP, RIP.

## 9.4 전송 제어 프로토콜 (TCP) - Part 1

### 1. 특징
- **연결형**: 3-way handshaking으로 연결 설정.
- **신뢰성**: 재전송, 순서 보장, 오류 검출.
- **스트림 전송**: 데이터를 바이트의 연속적인 스트림으로 취급.
- **전이중 통신 (Full-Duplex)**: 양방향 동시 통신 가능.
- **Piggybacking**: 데이터 전송 시 확인 응답(ACK)을 함께 실어 보냄.

### 2. TCP 세그먼트 구조
- **헤더 (20~60 바이트)**:
    - **발신지/목적지 포트**: 각 16비트.
    - **순서 번호 (Sequence Number)**: 32비트. 데이터의 첫 바이트 번호. 난수 ISN(Initial Sequence Number)으로 시작.
    - **확인 응답 번호 (Acknowledgement Number)**: 32비트. 다음에 받기를 기대하는 바이트 번호 (누적 ACK).
    - **헤더 길이 (HLEN)**: 4비트. 4바이트 단위.
    - **제어 플래그 (Control Flags)**: URG, ACK, PSH, RST, SYN, FIN.
    - **윈도우 크기 (Window Size)**: 16비트. 흐름 제어용 (수신 윈도우 rwnd).
    - **검사합 (Checksum)**: 16비트. 필수 사항.
    - **긴급 포인터 (Urgent Pointer)**: 16비트. URG 플래그 설정 시 유효.

### 3. TCP 연결 제어
- **연결 설정 (3-Way Handshake)**:
    1. **SYN**: 클라이언트 -> 서버 (ISN 전송, 연결 요청).
    2. **SYN + ACK**: 서버 -> 클라이언트 (서버 ISN 전송, 클라이언트 ISN+1 확인).
    3. **ACK**: 클라이언트 -> 서버 (서버 ISN+1 확인).
    - **SYN Flooding 공격**: 가짜 IP로 SYN만 대량으로 보내 서버 자원을 고갈시키는 DoS 공격.
- **데이터 전송**:
    - PSH (Push): 데이터를 즉시 상위 계층으로 전달 요청.
    - URG (Urgent): 긴급 데이터 처리 요청.
- **연결 종료 (3-Way or 4-Way Handshake)**:
    - **FIN**: 종료 요청.
    - **ACK**: 종료 확인.
    - **Half-Close**: 한쪽은 종료하고 다른 쪽은 계속 데이터를 보내는 상태 가능.

### 4. TCP 상태 천이 (State Transition)
- **주요 상태**:
    - `LISTEN`: 연결 요청 대기.
    - `SYN_SENT`: 연결 요청 보냄.
    - `SYN_RCVD`: 연결 요청 받음.
    - `ESTABLISHED`: 연결 수립 완료 (데이터 전송 가능).
    - `TIME_WAIT`: 연결 종료 후, 네트워크에 남은 패킷이 소멸될 때까지 대기 (2MSL).

### 5. 흐름 제어 (Flow Control)
- **슬라이딩 윈도우 (Sliding Window)**:
    - 수신측이 자신의 버퍼 여유 공간(`rwnd`)을 송신측에 알려주어 전송량을 조절합니다.
    - 윈도우 닫힘(Close), 열림(Open), 축소(Shrink).
- **어리석은 윈도우 신드롬 (Silly Window Syndrome)**:
    - 아주 작은 데이터를 빈번하게 전송하여 오버헤드가 커지는 현상.
    - **해결책**:
        - 송신측: **네이글(Nagle) 알고리즘** (데이터가 모이거나 ACK가 올 때까지 전송 지연).
        - 수신측: **클라크(Clark) 해결법** (버퍼가 충분히 비워질 때까지 윈도우 크기를 0으로 알림).
